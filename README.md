# 不求人 no-errands

> 「我沒辦法點瀏覽器裡的按鈕，這一步要請你自己做。」
> ——你的 agent，大概也講過這句

**人負責決定，agent 負責動手。**

現在的模型其實很會自己找路——沒有工具，它會自己寫一段程式去按按鈕。問題是它找到的路，常常是把你的滑鼠搶走、把整個螢幕截下來、或是直接打開你的 LINE（這些都在我們的測試裡真的發生過，見〈兩次事故〉）。

不求人不是教 agent 怎麼動手。它做的是**讓你放心讓它動手**：

| 你得到的 | 是什麼 |
|---|---|
| 🔑 **鑰匙** | agent 專用的瀏覽器 profile。你在想授權的網站登入一次，之後它自己進得去，碰不到你平常用的瀏覽器。 |
| 📮 **發件匣** | agent 想替你傳訊息時，只能起草。草稿出現在一個固定的本機頁面，你看過、可以改、按下核准才會送出。 |
| 🙈 **不打擾** | 它不模擬你的鍵盤滑鼠；會讓視窗跳到前景的步驟，只在你離開座位（閒置 3 分鐘）時才做，你一回來就收手、把畫面還你。 |
| 🎛 **你的規則** | 哪些 app 可以碰、哪些對話可以讀、未讀要不要保護——你說了算，寫在一個看得懂的檔案裡。 |
| 🤝 **好好交接** | 真的只有你能做的事（密碼、驗證碼、系統權限提示、實體操作），它先把其他事做完，一次問完，講清楚在哪裡按什麼，你做完它自己偵測到。 |

## 你大概遇過這些

| 本來做不到 | 之前 agent 會說 | 裝了之後（都實測過） |
|---|---|---|
| 登入之後才看得到的資料 | 「下載那一步需要你自己來」 | 你在 agent 專用的瀏覽器登入一次，之後它自己進得去；網頁上產生 token 也自己做、值直接寫進設定檔不經過對話。登入牆那題沒裝過不了、裝了 39 秒（便宜模型約 15 秒） |
| 聊天室裡的訊息 | 「拿手機匯出聊天記錄寄給自己」「要請管理員開權限」 | Mattermost 用你的 token 唯讀查詢（讀了不動已讀）；LINE 桌面版等你離開座位時自己找到指名群組、確認開對、匯出成文字檔（真機 12,562 B、356 行） |
| 替我回訊息 | 產一段草稿叫你自己貼 | 只能起草到發件匣；你看過、可改、按核准才由發件匣送出（自架 Mattermost 上核准後真的發出、退回的不發） |
| 畫面跳出東西要我按 | 「請按下一步」「請按『是』」 | 常見對話框與安裝精靈自己點完（NSIS、Inno Setup 點到完成再移除）；系統權限提示 1.2 秒認出、一句話交給你、你按完它自己偵測到 |
| 要我手動做一下再回報 | 「截圖給我看」「請用 Office 打開存一次」 | 自己截單一視窗來看；不開視窗重算公式、轉 PDF（Office 或 LibreOffice）；用 WSL 當第二台機器自己驗證 |
| 操作給別人看、教別人用 | 給你一份十幾步的教學 | 示範模式：放慢、每步截單一視窗，自動產出圖文步驟 |
| 它一動，我就不能用電腦 | 搶走視窗、動你的滑鼠、截整個螢幕 | 不注入鍵盤滑鼠；會跳到前景的步驟等你閒置 3 分鐘才做，你一碰鍵盤滑鼠就把視窗縮回去、把畫面還你 |

## 安裝

```powershell
# Windows（不需要先裝 Python：找不到可用的 Python 會自動下載 uv 單檔）
powershell -ExecutionPolicy Bypass -File setup.ps1 --user
```
```sh
# macOS / Linux
sh setup.sh --user
```

接著做自我檢查（每一階做真的測試，約 30–60 秒；**桌面那一項會開一個測試小視窗，請在方便的時候跑**）：

```sh
python doctor.py
```

裝完應該看到每一項一行 `ok`：`python`、`pkg_manager`、`browsers`、`desktop`、`browser`、`profile`。
（三平台在 GitHub Actions 上的實際輸出見 `docs/EXPERIMENTS.md`。）

只想在一個專案試用：把 `--user` 換成 `--project <專案資料夾>`。
已經有的 Python、你自己的 `CLAUDE.md` 內容、`settings.json`、同名的 skill 都不會被動到（有自動測試，見〈它在你電腦上放了什麼〉）。

> 也可以在這個資料夾開你的 agent 說一句「安裝不求人」——它會照 `CLAUDE.md` 的流程先告訴你要改什麼、裝好、問你方不方便再做會開視窗的檢查與示範。（這條流程本身**尚未實測**；上面的指令是實測過的。）

## 告訴它你的規則

直接用講的，agent 會改設定並回報改了什麼（每次修改都有紀錄）：

- 「我授權你用 Mattermost。」
- 「LINE 只能讀『某某群組』。」（加進白名單；其他有未讀的對話它不會打開）
- 「未讀保護關掉。」／「我要看你操作。」（觀看模式：瀏覽器有視窗、桌面操作可見）
- 「要跳到前景的事先問我。」（預設是等你閒置才做）

預設值是最保守的：沒授權的聊天、郵件、金融類 app 與網站一律不碰；未讀保護開啟；背景操作。
規則存在 `~/.no-errands/policy.json`。

讓它進某個網站：它開一個視窗停在登入頁，你登入，它偵測到就自己繼續。密碼永遠是你自己打。
（那個視窗是它控制的瀏覽器，所以規則是「登入期間不讀畫面、只檢查登入了沒」；要連技術上都讀不到，請它「用一般瀏覽器登入」——它會用沒有自動化通道的 Chrome 開同一個 profile，你登入完關掉視窗就好。）

## 發件匣

固定網址（預設 `http://127.0.0.1:8765/`；埠可改，存在 `policy.json` 的 `outbox.port`），可以釘成分頁。**一台電腦只有一個核准頁面**，裡面只放「要傳出去的訊息」——你只需要在這裡看 agent 準備替你送出的東西。

**示範劇本的核准有兩種模式**（只用於你登記成示範用途的主機；聊天、郵件等內建敏感 app 永遠不能用長期核准）：
- `page`（**預設**）：每一份劇本都出現在核准頁，你看過、按核准才會執行。
- `standing`：你在核准頁親自核准過一次「同一台主機、帳號涵蓋在內」的劇本之後，之後的劇本由發件匣伺服器自己核准（不是 agent 決定），每次自動核准都記在 decide-log；你只要撤銷或退回過一次，就暫停回到每份都看。自動核准的紀錄不會成為下一次自動核准的依據。
  設定：`policy.py domain set <主機> runbook_approval standing --reason "<你的原話>"`（改回 `page` 同一個指令）。

- 每則草稿顯示：**送到哪裡**（發件匣自己查出看得懂的名稱，不採用 agent 的說法；查不出來就不能核准）、agent 為什麼要傳、完整內文。
- 可以直接改內文再送，或退回並寫原因，agent 看得到。
- 你看到的和實際送出的是同一份：草稿在你打開頁面之後被改過，核准會被拒絕。
- 不會覆寫、不會重送；每次核准都留紀錄（含是哪個瀏覽器按的）。
- 目前能送：測試用的假聊天視窗（實測）；Mattermost（自架的真實 Mattermost 上實測：核准後真的發出、退回的不發；你自己的伺服器還沒送過——等你核准一則傳給自己的測試訊息）。LINE 送出**尚未支援**。

## 它會不會……

**打擾我？** 它保證的是**不模擬你的鍵盤滑鼠**。我們量過：一個視窗持續收字、另一個視窗同時被操作，200 個字一個不漏，游標沒被動過。
但「點一下按鈕」這種語意操作，有些程式會自己把視窗跳到前景（例如 LINE），會不會成功要看 Windows 當下的設定，我們量到過兩種結果。所以：
- 會跳前景的步驟**只在你閒置滿 3 分鐘時做**；途中你一碰鍵盤滑鼠（每 0.1 秒檢查一次），它就把那個視窗縮小、把畫面還你，下次你離開再做。
- 真的跳了前景，工具會偵測到、把前景還給你原本的視窗，並告訴 agent 發生了什麼。
- 會開視窗的測試與示範（自我檢查的桌面項、示範模式）會先問你方不方便。
- 檢測方法本身驗證過：在 CI 上刻意搶焦點、模擬打字與移動游標，量測工具都抓得到。
- **Windows 背景執行曾經會彈視窗**（2026-11-22 使用者回報「視窗一直彈出」）：沒有主控台的背景程序每呼叫一次命令列工具，Windows 11 就開一個終端機視窗並搶前景。已修（所有子程序都不開主控台視窗），並加了測試：從沒有主控台的程序連續呼叫 10 次，不可以出現任何視窗、前景不可以變；CI 上另有正對照，故意關掉修正時必須抓得到彈窗。

**亂碰我的帳號？** 聊天、郵件、金融類 app 與網站預設是禁區（桌面 app 和網頁版都是）。第一次要碰之前，它必須先在對話裡講清楚要用哪個、會讀什麼、不會做什麼，你說好才行——跳出登入視窗不算你同意。
已授權的聊天 app 走專用的守門工具：只碰你指名的對話；訊息輸入框、送出、貼圖、通話這些按鈕由程式擋下；選單裡只會點名稱**完全相符**的那一項（我們在選單裡放了「儲存並刪除」這種相似的陷阱項目測過）；任何非預期的確認框一律按取消。

**替我亂傳訊息？** 它沒有送出的能力，只有起草。送出在發件匣，由你按。Mattermost 的唯讀工具只會發 GET 請求（連搜尋都不支援，因為 Mattermost 的搜尋 API 是 POST），讀貼文不會把頻道標成已讀（實測過）。

**看到我的 token？** token 檔只由工具在執行時讀，不顯示、不寫進紀錄。另外可以加一組 Claude Code 權限規則：`python setup.py --user --guard-rules`——我們實測過，加了之後 agent 用 Read 工具或 `cat` 讀 token 檔都會被擋。

**有什麼擋不住？** 老實講：這些防線擋的是「太熱心」的 agent，不是惡意程式。能在你電腦上任意執行程式的東西，本來就什麼都能做；權限規則是前綴比對，刻意繞路還是繞得過。發件匣的核准頁對自動化瀏覽器會停用按鈕、伺服器也會拒絕，但刻意偽造還是繞得過。
另外，有些模型起草後會一直在前景等你核准；工具提供有上限的等待指令並提醒它結束回合，但沒辦法強制它停。
網頁與桌面的守門（`neb`／`ned`）只在 agent 經過它們時才生效。受管區塊要求網頁一律經 neb、桌面一律經 ned：**沒裝權限規則時，這是建議**——agent 直接呼叫瀏覽器或桌面工具就繞過了。**裝了權限規則（`python setup.py --user --guard-rules`）之後，直接呼叫會被擋**（實測擋得住：裸名稱、完整路徑的各種寫法、先 cd 再相對路徑、`bash -c` 包裝、PowerShell）；仍繞得過的：把工具名稱拆開再組起來、用 Python 子行程拼出路徑、用 `agent-b*` 這種萬用字元。副作用：只是提到工具名稱的指令（例如 `grep agent-browser`）也會被擋。**正在開發 no-errands 本身的機器，不要在使用者層級套用這條規則**（或等開發告一段落再開）：grep、git commit 訊息、跑測試，只要指令裡出現那兩個名稱都會被擋，而且 deny 沒辦法在專案層級蓋掉。兩個守門的放行清單是對工具每個子指令與選項逐項對過的（`docs/agent-browser-command-audit.md`、`docs/agent-desktop-command-audit.md`），升級版本要重對。

**權限規則一共四組（`--guard-rules`，選配、預設不開；開的時候預設開前三組，可以用 `--guard-groups` 自己選）：**

| 組 | 做什麼 | 機制 | 為什麼 |
|---|---|---|---|
| `direct-tools` | 指令裡出現 `agent-browser`／`agent-desktop`（Bash 與 PowerShell）就擋 | deny 規則 | 網頁一律經 neb、桌面一律經 ned |
| `token` | 預設不准 agent 讀 Mattermost token 檔；你特別設了白名單的專案資料夾才放行 | PreToolUse hook（`token_guard.py`） | token 只給工具在執行時讀 |
| `consent` | `policy.py grant`／`set`／`whitelist`／`domain`／`token-allow` 要先問你 | ask 規則 | 這幾個會擴大或改變你同意的範圍；`revoke`、`show` 只縮小或唯讀，不詢問 |
| `daily-ops`（不在預設裡） | 用安裝路徑呼叫的 gather、chat_guard、ned、neb、outbox、mm_ro、demo_runbook 直接放行，不再每次詢問，自動模式下也不會被當成可疑動作擋下 | allow 規則＋`autoMode` 條目 | 這些工具自己守門（白名單、授權、只讀、對外訊息只能起草），每次都問只會讓例行工作卡住；改變同意範圍的 policy.py 子指令不在裡面，`consent` 組照樣先問你 |

例：`python setup.py --user --guard-rules --guard-groups token,consent,daily-ops`。重新執行會先拿掉全部、再加這次選的；移除 `python setup.py --uninstall --user --guard-rules` 一律拿掉全部，只動我們自己的規則、hook 與 autoMode 條目。

**自動模式（auto mode）與 `daily-ops`：為什麼光有 allow 規則不夠**
- 自動模式下，每個動作由分類器判斷。Claude Code 一進自動模式，就會丟掉「可以執行任意程式」的寬鬆 allow 規則；`Bash("<python>" "<工具>.py":*)` 這種以直譯器開頭、後面接萬用字元的規則就屬於這種。
- 我們實測過（巢狀 `claude -p --permission-mode auto`，`claude-haiku-5-5`，任務寫在專案檔案裡，不是你在對話裡說的）：
  - 只有 allow 規則：4 次都被擋。
  - 改成 `.cmd` 啟動檔的 allow 規則：2 次都被擋。
- 官方支援的做法是 `~/.claude/settings.json` 的 `autoMode` 區塊：寫給分類器讀的文字規則，`environment` 說明這套工具是你自己的，`allow` 說明可以放行哪些。這個區塊只在使用者層級有效，專案設定不讀，所以 `--project` 安裝時這部分不起作用。
- 加上 `autoMode` 條目後：
  - 同樣由檔案下指示的匯出：2 次通過 1 次。沒通過的那次，是檔案要它加上「使用者已同意」的旗標，被分類器認定在削弱監督；這是對的，「你同意了」只能由你在對話裡說。
  - 由檔案下指示的 `policy.py grant`：2 次都沒執行，政策沒有被改。
- 你在對話裡直接要求的例行工作（例如「更新聊天收集」），有沒有 `autoMode` 都會放行（4/4）。
- 小結：`daily-ops` 讓例行工作不會因為指令來自工具說明或排程就被擋；授權與同意範圍的改變，永遠要你本人說。
- **不開 `consent` 時**：policy.py 的 grant／set／whitelist／domain／token-allow 不會跳出確認，但也不在放行規則裡，改由自動模式的分類器判斷——你在哪個對話裡明確要求，那個對話就能做；agent 自己起意、或靠別的 session 轉達的，會被擋（`autoMode` 條目也寫明了這幾個不在放行範圍）。不用自動模式的話，這些指令照 Claude Code 平常的方式問你。

**token 白名單**：`policy.py token-allow add <專案資料夾> --reason "<你的原話>"`（寫 ledger；這個指令本身在 `consent` 組裡要先問你）。
為什麼用 hook 不用 deny：Claude Code 的 deny 規則沒辦法被專案層級蓋掉，做不到「白名單時可以」。hook 在每次 Read／Bash／PowerShell／Grep／Glob／Edit／Write 之前讀政策檔判斷：工具輸入裡出現 token 檔的路徑（各種寫法）或檔名、而目前專案（Claude Code 啟動的資料夾）不在白名單 → 擋下並說明。
巢狀 `claude -p`（`claude-haiku-5-5`）實測：不在白名單的專案，Read 與 `cat` 都被擋、沒有洩漏；白名單專案兩種都讀得到。額外負擔：每次符合的工具呼叫約 60 毫秒（啟動一次 Python）。
**失效時一律放行，不會讓 Claude Code 不能用**：hook 指令先檢查腳本在不在，不在就直接放行。所以刪掉或搬走 `~/.no-errands` 也不會擋住任何工具呼叫。腳本出錯、政策檔壞掉或不存在、hook 逾時，一律放行。巢狀實測過這四種情況（permission_denials 都是 0）。移除 no-errands（`setup.py --uninstall`）時，這筆 hook 和規則會一起拿掉。
限制和權限規則一樣：把路徑拆開再組、用萬用字元或另一支程式去讀，hook 看不到；失效放行時當然也就不擋。
**副作用**：只看路徑欄位（Read／Edit／Write 的檔案路徑、Grep／Glob 的資料夾）和殼層指令。Edit／Write 寫進去的內容、Grep 的搜尋字串提到 token 檔名，不算讀檔。但**殼層指令裡只要出現 token 檔名就會被擋**，例如 `grep -rn <token 檔名> docs/`，或在 heredoc 裡寫一段提到它的腳本。開發 no-errands 的 session 實測：2169 次工具呼叫中有 11 次（0.5%，全是 Bash）會被擋。避開方式：要寫這種腳本就用 Write 工具，或把開發用的專案資料夾加進 token 白名單（要你同意）。

聊天 app 的守門（`chat_guard.py`）**不加詢問**：授權與白名單由它自己把關，白名單內的對話可以直接匯出、同步，無人在場也跑得完；白名單外的一律被它拒絕。

瀏覽器的守門只認得公開的聊天／郵件網站（Gmail、Slack、LINE 網頁版……）和政策檔裡登記的 Mattermost 網址；**自架在內網、或經 SSH 通道從 `localhost` 開的聊天或信箱服務，目前會被當成一般網站、不設防**。現在只有 Mattermost 能登記（政策檔的 `mattermost.url`）；任意網址的登記方式還在做。

## 兩次事故

開發期間，測試用的 agent 出過兩次事。規則就是這樣來的。

1. **它自己打開了 LINE。** 一道虛構的考題提到 LINE，裝了工具的測試 agent 就把真的 LINE 桌面版開到登入畫面；使用者以為是需要的，掃碼登入了，它接著瀏覽了聊天列表。沒有送出任何訊息。→ 個人帳號的同意閘門、敏感 app 預設禁區、每個桌面指令都要寫明目標 app。
2. **它搶了滑鼠、截了全螢幕。** 沒裝工具的對照組為了完成任務，自己寫程式把視窗拉到最前面、模擬滑鼠、把整個螢幕截下來——當時使用者正在用電腦。→ 「不打擾」成了獨立的規則與機制（閒置閘門、偵測與交還）。

兩次的教訓是同一句：**能力是真的，所以守門要靠機制，不能只靠寫在文件裡的叮嚀。**

## 聊天收集（gather）

指定聊天室與起始時間，之後的訊息全部收下來，隨時增量更新——不需要 bot、不需要管理員：
`python ~/.no-errands/bin/gather.py add --service line --chat <聊天室> --since 2026-11-01`，之後 `gather.py sync --all`、`gather.py status`。要讓 context-gather 直接 Grep，加 `--dest <專案>/cache/line/<id>/`（寫成它的每日 md 格式）。

限制（實測）：
- LINE 桌面版匯出的範圍＝**已同步到這台電腦的歷史**（實測：登入時回補約前三週），往上捲動不會變多；更早的請用手機「匯出聊天記錄」再 `gather.py import`。
- 匯出要打開對話（會變已讀），所以 LINE 只收白名單裡的聊天室；畫面操作只在你離開座位時做。
- 附件只記佔位（貼圖、照片、檔案），不下載。LINE 匯出沒有訊息 id，合併靠序列對齊，接不上的地方會明確標成缺口。
- 定時自動同步還沒做（目前要叫 agent 跑 `sync`）。

## 它在你電腦上放了什麼

- `~/.no-errands/`：`bin/`（agent-desktop、agent-browser 單檔，版本與 sha256 釘在 `versions.json`；工具腳本）、`browser-profile/`（agent 專用 profile）、`policy.json`（你的規則）、`config.json`、`capabilities.md`（自我檢查結果）、`outbox/`（發件匣紀錄）、各工具的操作紀錄 `*-ledger.jsonl`、`playbook-local/`。
- 你的 `CLAUDE.md`：多一段 `<!-- no-errands:start -->`…`<!-- no-errands:end -->`，其餘內容一個位元組都不動（移除後逐位元組還原）。
- skill：`~/.claude/skills/no-errands/`（或專案的 `.claude/skills/`），裡面有一個標記檔；已經有別人的同名 skill 時會停下來、不覆蓋。
- 只有在找不到可用 Python 時才會多一個 `uv` 單檔，它帶的 Python 放在 uv 的預設位置。
- 不改 PATH、不需要管理員權限。

完全移除：

```sh
python setup.py --uninstall --user          # 拿掉 skill 與受管區塊
python setup.py --uninstall --user --guard-rules   # 若加過權限規則
```

`~/.no-errands/`（你的規則、登入過的 profile、發件匣紀錄）會留著，要不要刪你決定。

## 一起養 playbook

agent 走通一條路（某個網站怎麼登、某個程式的隱藏指令列、某個安裝精靈怎麼過），就把它寫成一頁放進 `playbook/`，下一個人的 agent 直接照走。現有：Windows Chrome 的 UIA 操作、Linux 免 sudo 補瀏覽器系統庫、LINE 桌面版、把 WSL 當第二台機器。

現在最想要的：context-gather 記成 `denied` 的來源、各種 token 的申請流程、你常用但只有圖形介面的工具。含私人資訊的放 `~/.no-errands/playbook-local/`。

## 和 context-gather 的關係

context-gather 讓 agent 知道脈絡；不求人讓 agent 有手腳，而且是你管得住的手腳。前者記成 `denied`、或寫著「請手動」的步驟，就是後者要接的地方。
