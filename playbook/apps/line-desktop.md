# LINE 桌面版（Windows）：找到指名對話、確認身分、匯出聊天紀錄

> 狀態：Windows 11、LINE 26.x（Qt 介面）、單一白名單群組。步驟 1–4 在真機實測（2026-11-21，使用者在場、事前同意）。
> 步驟 5（彈出選單）的根因在 CI 用 Qt6 重現並解決；完整匯出流程在假聊天視窗（含誘餌選單項目）CI 34/34。
> 真機匯出（閒置閘門）2026-11-22 一路走完：12,562 B、356 行，三道身分檢查都過。
> 前提：使用者已在對話中授權 LINE（`policy.py grant line`），且該對話在白名單裡。全程走 `chat_guard`，
> 不用 `agent-desktop` 直呼、不送鍵盤、不用座標。一行指令：`chat_guard.py line export --chat <名稱> --to <資料夾> --wait-idle`。

## 走得通的路

1. **主視窗**：`list-windows --app LINE.exe`，標題為 `LINE` 的那一個。最小化時先 `restore --window-id`
   （這一步會把 LINE 拉到前景 → 只在使用者閒置時做：`--wait-idle`，或事前告知）。
2. **定位對話**：聊天清單是主視窗裡唯一的 `listbox`，底下每個對話一顆 `button`，名稱打包成
   `<對話名稱>, <N人>, [<未讀數>, ]<最後一則預覽>, <日期>`。**只在這個 listbox 裡比對**：名稱以對話名稱開頭、
   下一個字元是分隔符（`,`），且恰好一個。清單字串含其他對話的預覽——只把符合項的字串拿出來，其餘不輸出。
3. **開啟**：對符合項做語意 `click`（UIA press）。
4. **確認開著的是誰（決定性訊號）**：右側窗格會出現一組 7 顆按鈕的標頭工具列，第一顆的名稱是
   `<對話名稱>, <N人>`；其餘依序是「關閉提醒、以個別視窗開啟、搜尋聊天、開始通話、記事本、其他功能」。
   第一顆名稱比對相符才繼續。（清單項目沒有 selected 狀態、右側也沒有獨立的標頭文字節點——別找那些。）
5. **「其他功能」→「儲存聊天」**：語意點「其他功能」後，彈出選單是**另一個頂層視窗**（agent-desktop 的視窗清單看不到）。
   `scripts/popup_menu.py`：Win32 列舉同 pid、點擊後新出現的可見頂層視窗 → 對那個 HWND 做 UIA FromHandle 讀項目名稱與位置 →
   **只點名稱完全等於「儲存聊天」的那一項**（投遞滑鼠訊息到該視窗；游標不動、不是全域輸入）。名稱不唯一或找不到 → 關掉選單、停手。
6. **另存新檔對話框**：同 pid 的系統對話框。
   - 先讀檔名欄的預設值，**必須含對話名稱**（LINE 會把對話名稱放進預設檔名），否則按取消、停手。
   - 寫**內層 Edit**（automation id 1001，role textfield）而不是外層 ComboBox，寫完讀回比對。
   - 按「存檔」（id 1）。出現「確認另存新檔」→ 按「否」再取消、停手（**絕不覆寫**）。
   - 對話框若沒採用寫進去的路徑、照預設檔名存到它自己的資料夾（網址列顯示的那個）→ 去那裡找剛存的檔案搬過來。
   - 存好後等檔案停止變大，再驗身分：**LINE 的匯出檔沒有標頭、不含對話名稱**（第一行是日期，其後「HH:MM 發言者 內容」），所以改數「不同發言者數 ≤ 標頭的 N 人」（只數、不輸出）；不符就刪檔、停手（刪不掉會照實說檔案留在哪）。
7. **收尾**：`minimize --window-id <主視窗>`——前景會回到使用者原本的視窗，游標不動（實測）。
   途中使用者一碰鍵盤滑鼠（每 0.1 秒檢查），立刻最小化 LINE 並停手。

## 走不通的路與原因

- **在主視窗的 UIA 樹裡找選單項目**：找不到。不是無障礙沒開，是選單長在另一個頂層視窗（Qt 的 popup），被視窗清單濾掉。
- **UIA Invoke 點選單項目**：會被「項目打開模態對話框」卡住（呼叫不返回）→ 用投遞訊息。
- **語意點擊會讓 LINE 自己跳到前景**：第一次點清單項目時前景被換走（游標沒動）→ 閒置閘門＋最小化交還。
- **隔太久再檢查會看到空白窗格**（「開始聊天吧！」）：視窗被重開過，選取狀態被重置。開啟後要立刻確認。
- 「以個別視窗開啟」沒試過（不需要了）。

## 驗收方式

標頭工具列「名稱, N人」（開啟後）＋另存新檔對話框的**預設檔名**含對話名稱（存檔前，LINE 產生）＋匯出檔**不同發言者數 ≤ N**（存檔後，只數）。回報只給：檔案存在、大小、行數、格式是否符合。
聊天內容不寫進 log、playbook、repo。

## 交人點（自動路線停手時的備案）

> 「我已經把〈對話〉打開了。請在 LINE 右上角點 **其他功能（⋯）→ 儲存聊天**。存檔視窗跳出來之後不用管，
> 我會接手填路徑、存檔、確認，然後把 LINE 縮回去。」

接手方式：輪詢同 pid 的另存新檔對話框（上限約 120 秒），一出現就照第 6 步做；逾時就收攤、交還前景、回報。
人做完不用回報：對話框出現就是訊號。
