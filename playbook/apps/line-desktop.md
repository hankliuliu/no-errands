# LINE 桌面版（Windows）：找到指名對話、確認身分、匯出聊天紀錄

> 狀態：Windows 11、LINE 26.x（Qt 介面）、單一白名單群組實測（2026-11-21）。
> 協助式匯出（下面「交人點」）**尚未在真實 LINE 走完**；匯出的身分驗證流程已在假視窗與 CI 通過。
> 前提：使用者已在對話中授權 LINE（`policy.py grant line`），且該對話在白名單裡。全程走 `chat_guard`，
> 不用 `agent-desktop` 直呼、不送鍵盤、不用座標。

## 走得通的路

1. **主視窗**：`list-windows --app LINE.exe`，標題為 `LINE` 的那一個。最小化時先 `restore --window-id`
   （這一步會把 LINE 拉到前景——事前告知使用者）。
2. **定位對話**：聊天清單是主視窗裡唯一的 `listbox`，底下每個對話一顆 `button`，名稱打包成
   `<對話名稱>, <N人>, [<未讀數>, ]<最後一則預覽>, <日期>`。**只在這個 listbox 裡比對**：名稱以對話名稱開頭、
   下一個字元是分隔符（`,`），且恰好一個。清單字串含其他對話的預覽——只把符合項的字串拿出來，其餘不輸出。
3. **開啟**：對符合項做語意 `click`（UIA press）。
4. **確認開著的是誰（決定性訊號）**：右側窗格會出現一組 7 顆按鈕的標頭工具列，第一顆的名稱是
   `<對話名稱>, <N人>`；其餘依序是「關閉提醒、以個別視窗開啟、搜尋聊天、開始通話、記事本、其他功能」。
   第一顆名稱比對相符才繼續。（清單項目沒有 selected 狀態、右側也沒有獨立的標頭文字節點——別找那些。）
5. **另存新檔對話框**（使用者點出來之後，見交人點）：同 pid 的系統對話框。
   - 先讀檔名欄的預設值，**必須含對話名稱**（LINE 會把對話名稱放進預設檔名），否則按取消、停手。
   - 寫**內層 Edit**（automation id 1001，role textfield）而不是外層 ComboBox，寫完讀回比對。
   - 按「存檔」（id 1）。出現「確認另存新檔」→ 按「否」再取消、停手（**絕不覆寫**）。
   - 存好後只讀檔案**第一行**比對對話名稱，不符就刪檔、停手；相符才算行數、大小。
6. **收尾**：`minimize --window-id <主視窗>`——前景會回到使用者原本的視窗，游標不動（實測）。

## 走不通的路與原因

- **「其他功能」的彈出選單不在 UIA 樹裡**：語意點擊會打開它，但沒有 menu surface、沒有新視窗、
  主視窗樹裡也沒有 menuitem。要點裡面的「儲存聊天」只能座標或鍵盤 → 不做，改成交人點。
- **語意點擊可能讓 LINE 自己跳到前景**：第一次點清單項目時前景被換走（游標沒動）。事前告知；
  做完用最小化交還。
- **隔太久再檢查會看到空白窗格**（「開始聊天吧！」）：視窗被重開過，選取狀態被重置。開啟後要立刻確認。
- 「以個別視窗開啟」尚未嘗試（可能讓標題直接等於對話名稱、選單也可能可及）。

## 驗收方式

另存新檔對話框的**預設檔名**含對話名稱（存檔前）＋匯出檔**第一行**含對話名稱（存檔後）。
兩者都是 LINE 自己產生的，在讀到任何聊天內容之前就能比對。回報只給：檔案存在、大小、行數、格式是否符合。
聊天內容不寫進 log、playbook、repo。

## 交人點（只有這一下）

> 「我已經把〈對話〉打開了。請在 LINE 右上角點 **其他功能（⋯）→ 儲存聊天**。存檔視窗跳出來之後不用管，
> 我會接手填路徑、存檔、確認，然後把 LINE 縮回去。」

agent 端：`chat_guard line export --assist --chat <名稱> --to <資料夾>`（規劃中）——輪詢同 pid 的
另存新檔對話框（上限約 120 秒），一出現就照上面第 5 步接手；逾時就收攤、交還前景、回報。
人做完不用回報：對話框出現就是訊號。
